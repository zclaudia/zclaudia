## 1. 目标与范围

验证用户在两个客户端的 **Automations tab** 中能完成相同的操作，看到含义一致的数据、状态和反馈，同时布局适合各自的输入方式。

覆盖：入口与返回、Backend / Project 范围、列表和侧栏树、新建表单、五种 Trigger、Activity / Workflow Action、立即运行、启用 / 停用、删除、刷新、错误反馈、主题、小屏与软键盘、跨端数据核对。

Activity、Workflows、System、Runs 仅验证导航和与 Automations 有关的结果，不展开它们的完整功能测试。当前页面没有编辑 Automation 的入口，不把“编辑表单”当成已有能力。调度精度、模型质量、权限工作流内部逻辑不属于本轮重点。

“一致”包含三个维度：

1. **两端一致**：同一 Backend、同一范围、同一数据版本下，字段含义、可执行操作、分组与结果一致。
2. **页面内一致**：标题 / 范围、侧栏树、卡片、计数、操作结果相互匹配。
3. **交互前后一致**：刷新、返回、切换主题、横竖屏和重开应用不造成错误状态或操作对象变化。

两端出现同样的缺陷仍判 FAIL；不以“一样错误”满足一致性。

## 2. 已确认的实现及验收边界

| 代码事实 | 对测试的影响 |
| --- | --- |
| 两端共用 `AutomationContent`、`AutomationsTab` | 共用业务断言，分别执行桌面鼠标 / 键盘与模拟器触摸事件 / Android 输入路径 |
| `useIsMobile` 以小于 768 CSS px 判断移动布局，也支持 `forceMobile` | 767 / 768 / 769 是断点回归点；正式实际应用验收不使用 `forceMobile` 掩盖自然布局问题 |
| 移动端无项目范围时隐藏重复的内容标题；项目范围下保留范围标题 | 不要求标题栏数量逐像素相同；要求页面身份与项目范围明确 |
| 卡片名称桌面单行省略、移动端最多两行；元数据允许换行 | 验证不覆盖按钮、不同任务仍可区分；允许卡片高度不同 |
| Trigger 为 Manual / Interval / Cron / Once / Event；Action 来自服务端目录或 Workflow | 检查所有分支；两端目录相同是比较的前提，不能硬编码所有插件选项 |
| 未指定 projectId 时服务端返回该 Backend 的全部 Automation | “无项目过滤”不等于“只含 Global”；卡片的 Global 表示项目归属，不能混淆 |
| 系统 Automation 不允许普通修改 / 删除，但卡片目前仍渲染操作按钮 | 验收期望是 UI 明确表达限制；“点击无反应”不是通过结果 |
| 当前列表映射只有 idle / disabled，runCount 固定为 0，未映射 lastError | 不虚构已有运行中 / 成功 / 失败卡片 UI；运行闭环用 Runs 和真实记录证明，缺少操作反馈单独报问题 |
| 页面通过加载和显式 Refresh 取数 | 本轮跨端一致性以另一端显式刷新完成为同步点，不默认已有实时同步 SLA |

用户截图作为桌面结构参考：导航选中、Automations 标题、数量、Active 分组、卡片信息和右侧操作。它不是所有尺寸的像素模板，也不是对系统项可操作性的产品授权。

### 执行前检查

- 两端使用同一候选版本；记录 commit、工作区差异摘要、包版本、包哈希、构建方式。
- 使用专用 Backend A 和 B、专用数据目录与测试项目；桌面和移动端都能实际访问同一个 A。移动端按目标产品连接方式经 Gateway 接入，记录链路版本。
- 对齐主题、语言、时区（默认 Asia/Shanghai）、Action 目录版本及 Workflow 数据；比较期间避免无关数据变更。
- 模拟器准备中文输入法并确认聚焦字段时 Android 软键盘实际显示；必要时开启连接硬件键盘时仍显示屏幕键盘的系统选项。中文组合输入通过 IME 验证，不用直接设置 DOM 值或 ADB 文本注入代替。保留 Android 系统返回、键盘和日期选择器行为。
- 记录当前模拟器分辨率、密度、字体缩放、方向和导航模式；M2 变更后恢复原值。ADB 命令明确指定 `-s emulator-5554`（重启后重新确认 serial），不修改其他设备或现有端口转发。
- 可读取测试 Automation ID、运行记录和脱敏请求日志。工具访问和设备连接不可用时记 BLOCKED。
- 不运行会清空日常数据库的现有 `cleanDb` fixture；不以现有 README 的历史通过率作为本轮证据。

## 5. UI 一致性验收规则

| 维度 | 必须相同 | 允许差异与拒绝条件 |
| --- | --- | --- |
| 信息 | 名称、项目归属、Trigger / Action、启用状态、数量 | 桌面省略 / 移动端换行可不同；必须有可访问方式区分任务，不能只依赖移动端没有的 hover |
| 操作 | New、Refresh、Run now、Enable / Disable、Delete 的含义与结果 | 桌面 tooltip / 移动端可访问名称可不同；两个 Play 图标不能导致运行与启用混淆 |
| 导航 | 当前 tab、Backend、项目范围与选中对象 | 桌面侧栏 / 移动端抽屉不同；不得重复无意义标题、缺返回入口或范围不明 |
| 样式 | 同主题下字体层级、语义颜色、图标、边框、圆角和选中 / 禁用规则 | 系统字体渲染允许细微差别；深色主题不得出现不可读字段或突兀白色面板 |
| 表单 | 字段、默认值、选项、必填判定、错误含义、提交结果 | 移动端可以换行、放大按钮、使用原生日期选择器；不能少字段或遮挡 Create / Cancel |
| 状态 | loading / empty / error / disabled 含义 | 不允许把请求失败显示为正常空数据；不能仅颜色变化而无可理解的状态 |
| 触控 | 点击 / 触摸只命中目标操作 | 文本与按钮及相邻按钮的有效热区不能产生歧义；伪元素扩大热区也要测 |

视觉判定方法：

- 同设备、同主题、同视口与同数据状态比较基线截图；桌面与移动端做语义、层级和布局对照，不直接整图像素相减。
- 页面不产生意外水平滚动；无文字 / 按钮覆盖、裁切、越过安全区；长内容只能在预期容器滚动。
- 同环境截图叠加检查，稳定元素偏移超过 2 CSS px 作为人工复核信号，不机械判错；文字抗锯齿不能掩盖结构变化。
- 本计划建议移动端主要操作目标达到约 44×44 CSS px 的等效有效热区，作为体验检查目标而非宣称现有规范；不足记录测量值和误触结果。热区重叠或误触运行 / 删除直接阻断。
- 每个高风险按钮测中心、四侧边缘，以及与邻近文本 / 按钮之间的间隙。每次使用独立可恢复数据，检查实际目标 ID，而非仅看动画。
- 可遮罩时间、随机 ID 和系统时钟；不得遮罩标题、数量、错误、状态与按钮。

| --- | --- | --- |

| A02 列表与范围 | S1：无项目过滤 → P1 → P2 → P0；核对卡片和计数 | 计数等于当前结果；Active / Disabled 分组正确；卡片 scope 与实际项目一致；空项目显示正常空态 |
| A03 侧栏与主列表 | 展开项目树，选一条任务；再创建、启停、删除专用任务并重新查看树 | 高亮对象正确且可找到；树与主列表名称 / 状态 / 存在性一致；不得残留已删条目或选中错误 ID |
| A04 新建基础路径 | New → 输入中文名称 → Manual → 专用无害 Activity → Create；再测 Workflow Action | 表单字段与选项一致；创建完成后表单收起，准确新增 1 条；名称、Action 与项目范围持久化正确 |
| A05 五种 Trigger | 分别选择 Manual / Interval=60 / Cron=`0 9 * * *` / Once=将来时间 / Event=专用事件名，创建独立任务 | 仅显示相关输入；摘要、保存参数与所选一致；Once 两端对应同一时刻；保存后暂停定时测试任务避免背景干扰 |
| A06 必填与错误 | 空白名称、Workflow 未选择、Activity 必填空值、Once 为空；补齐后重试 | 禁用或明确错误；不生成无效任务；错误不被键盘遮挡；修正后一次成功；状态两端一致 |
| A07 菜单与键盘 | 展开 Trigger / Action / Workflow；选中、点外部关闭；桌面方向键 / Enter / Escape / Tab；移动端滚动选项 | 选项可达、选中明确，未选择关闭不改值；菜单不被容器裁切或伸出屏幕；关闭后焦点合理 |
| A08 取消与重开 | 输入表单 → Cancel → New；再用 New 折叠并展开；另测 Create 成功后再次 New | 不误提交；记录草稿保留 / 清空规则并验证两端相同；成功后的名称等已重置字段不可出现上一任务值，保留默认选项不当成失败 |
| A09 启停闭环 | S1 的一条普通任务 Disable → Refresh → Enable | 仅目标 ID 改变；分组和计数随之变化；图标 / 名称 / 状态同步；重开页面仍正确 |
| A10 立即运行 | S5 的 Manual 任务单击 Run now；在 Runs 核对，再返回列表 | 恰好新增一次对应 Automation 的真实运行；用户能辨认提交结果或看到可用结果入口；不把卡片静态绿点当成功证据 |
| A11 删除闭环 | 删除专用 Disabled 任务；刷新并重开页面；从另一端刷新 | 目标消失且计数正确；其他任务未变；当前实现直接删除，不虚构确认弹窗；若后续加确认，补测取消不删除 |
| A12 系统项限制 | S0：检查系统标识及 Disable / Delete；必要时只在独立环境尝试操作 | 系统项不能变更，且 UI 清楚表达限制；可点击后静默失败判 FAIL；不通过删除真实系统数据构造场景 |
| A13 移动卡片与误触 | S3 / S6：竖屏，触摸长名称、元数据、按钮间隙；逐个运行 / 启停 / 删除专用副本 | 名称与摘要不覆盖按钮；文本和间隙不误发业务操作；相邻按钮不串操作；可区分两个长名称任务 |
| A14 IME 与安全区 | 移动端用中文 IME 输入名称 / 多行配置；显示键盘时滚动并点 Create / Cancel；Once 用实际日期控件 | 组合输入不提前提交、不丢字；焦点字段、错误、底部按钮能滚动到可见；系统栏不遮控件；日期值不意外改变 |
| A15 双向跨端一致 | 桌面创建 X → 移动端 Refresh；移动端 Disable X → 桌面 Refresh；桌面 Enable → 移动端 Refresh；移动端删除 → 桌面 Refresh | 每个同步点按 X 的 ID 比对名称、scope、trigger、action、enabled；树与列表均正确；显式刷新后仍旧数据判 FAIL |
| A16 Backend / Project 隔离 | A/P1 → B 的同名项目或任务 → A/P2 → A/P1；弱网下快速切换范围 | 迟到响应不能覆盖当前范围；标题、列表、树和写请求目标一致；误操作其他 Backend / Project 直接阻断 |
| A17 失败与恢复 | 分别在列表加载、Create、Enable / Disable、Delete、Run now 时中断测试链路；恢复后显式刷新 | loading / error / empty 可区分；失败有可理解反馈；不显示虚假成功；恢复不重复写入；实际已提交但响应丢失时先查 ID / run 再决定重试 |
| A18 主题与布局 | D1 / M1 各在亮、暗主题检查列表、禁用卡片、表单、菜单、错误；D2 缩窗 | 层级和颜色语义一致；无不可读文字、错位、越界；所有主要操作可达；选中 / 禁用不能丢失 |

## 7. P1：完整回归与探索

| ID | 操作与重点 |
| --- | --- |
| B01 Interval 边界 | 空、0、-1、1、小数、非数字、极大值；输入与保存值不得悄悄不一致。当前 `parseInt(value) || 60` 会归一化部分输入，作为待验证风险，不把静默改写预设为正确 |
| B02 Cron / Event / Once 边界 | 空白、非法 Cron、长事件名、过去时间；记录后端实际支持规则；错误能定位问题。对未定义的过去时间策略单列待决策项 |
| B03 Action 切换 | 填 Activity A → B → Workflow → A；旧 config 不混入新 Action；Flow Control / Permission 分类不作为 inline Activity 选项；Workflow 目录包含适用的全局项 |
| B04 SchemaForm 类型 | string / multiline / number / boolean / enum；中文粘贴、换行、清空、必填布尔 false、数字 0；不把合法 false / 0 误判为空 |
| B05 多次输入与重复操作 | 慢响应期间快速双击 Create / Run now、连续启停和刷新；检查重复请求 / 记录。单次操作仍在处理中应有明确状态，不能因无反馈导致用户无意重复提交 |
| B06 长列表滚动 | S6 滚动到末尾，操作最后一条，回到顶部；打开长 Workflow 菜单；侧栏选中屏外任务；无错误行、横向溢出或滚动被锁死 |
| B07 旋转与字体放大 | M2 竖→横→竖，系统字体 100% / 130% / 150%（按设备支持档位）；列表、已填表单和开菜单时分别执行；不丢输入、不跳 Backend；横屏跨 768 后检查导航仍可用 |
| B08 Android 返回层级 | 键盘、Select、抽屉、Automations 页面依次打开并按系统返回；优先关闭当前可关闭层，不误提交 / 删除；不能用标题返回替代系统返回测试；草稿退出策略记录为产品契约 |
| B09 前后台与重开 | 已加载列表和编辑表单时切后台再返回；退出重开后进入相同范围并刷新；持久化数据一致、没有自动重放操作；草稿是否跨重开保存不预设为已有能力 |
| B10 目录加载异常 | `/api/workflow-step-types` 或 `/api/workflows` 失败 / 延迟 / 空目录；不能留下无解释空选择器，不能提交不可识别 Action；恢复后可用 |
| B11 表单与范围切换 | 在 A/P1 填表但未提交，切到 A/P2 或 B 再检查；草稿应明确清空或明确归属，不能静默向新范围提交旧表单 |
| B12 可访问性 | 桌面纯键盘走完创建 / 启停；移动端屏幕阅读检查图标名称、表单标签、状态及顺序；Run now 与 Enable 可区分，焦点可见且无陷阱 |
| B13 两端竞争 | 两端均加载 X；一端删除，另一端再启停 / 触发；显示失效 / 失败并刷新，不复活 X，不操作同名 Y |

## 8. 桌面应用 / 模拟器执行与证据

### 一条核心执行链

桌面应用进入 Automations → 选择 A/P1 → 创建 Manual + 测试 Workflow → 检查列表与树 → 移动端进入相同范围并 Refresh → Run now → Runs 核对真实运行 → 移动端 Disable → 桌面 Refresh 核对 → 桌面 Enable → 移动端 Refresh 核对 → 移动端 Delete → 两端 Refresh 核对 → 返回应用。

这条链证明两端交互和持久化闭环，其余分支仍按用例表单独执行。

### 执行工具分层

- **实际应用验收层**：桌面安装包使用鼠标 / 键盘；模拟器内实际 APK 使用点击 / 滑动产生的触摸事件、Android IME、系统返回及旋转。首轮人工执行并录屏，已有桌面 UI 工具可辅助操作模拟器窗口；ADB 可用于指定模拟器的控制、日志与采证。浏览器移动视口不能替代此层。
- **自动化固化层（待实现）**：选择能操作目标桌面壳 / Android APK 的驱动，先验证实际包与 WebView 可访问性。定位优先可访问名称和稳定对象标识；缺少 ID 时登记补充需求，不用易变的第几个按钮定位危险操作。
- **快速回归层**：现有 Playwright 配置针对浏览器页面，可补充宽度、主题、菜单、布局和视觉回归；它不能代表 macOS 安装包或 Android APK 已通过。
- 当前未发现专用 Automations Playwright spec；已有组件测试不能代替本计划的实际应用结果。建议后续新增 `e2e/tests/automations-ui.playwright.spec.ts`，本轮不声称已编写或运行。

所有写操作等待明确结果或超时，不靠固定 sleep 推断成功。建议将受控正常网络下“用户操作到 UI 稳定”的预算设为 5 秒，故障识别预算 15 秒并记录实际耗时；这是本计划的初始执行预算，不是已存在的产品 SLA。真实运行完成使用独立超时，不与 UI 响应混为一谈。

### 每个结果至少保存

1. 用例 ID / 子场景、设备、版本、主题、视口、字体缩放、Backend / Project / Automation ID。
2. 操作前后原始截图；菜单、键盘、系统返回、误触或异步问题保存连续录屏。
3. 对创建 / 启停 / 删除 / 运行附脱敏请求结果或真实记录，证明作用对象与次数；单有 HTTP 200 不能证明 UI 通过。
4. 预期、实测、结论（PASS / FAIL / BLOCKED / NOT RUN / N/A）、缺陷链接。

建议证据目录：`artifacts/automations-ui/<run-id>/<case-id>/<device>/<theme>/`。命名包含动作阶段；截图保留原始尺寸。做对照图时另存副本，不覆盖原图。

推荐成对截图状态：S0 截图参考态、S1 混合状态、空项目、New 默认态、五种 Trigger 展开态、Workflow 下拉、校验错误、长名称、键盘展开、深色主题、写操作前后。

## 9. 首轮重点风险（代码审阅，尚非实际应用结论）

| 风险 | 依据 | 对应用例 |
| --- | --- | --- |
| 请求失败被当成空列表，启停 / 删除 / 运行失败被吞掉 | 列表 `.catch(() => [])`，写操作 `.catch(() => {})` | A12、A17 |
| 系统项可点击操作与实际不可变规则冲突 | 卡片未区分 `isSystem`，服务端拒绝 update / delete | A12 |
| 图标热区可能相互覆盖或侵入文本 | `IconButton` / Delete 在移动端通过 `::before` 扩大区域，操作间距较小 | A13 |
| 侧栏树与列表分别取数，变更后可能不同步 | Tree 订阅 refresh nonce，AutomationsTab 的变更仅刷新本地列表 | A03、A15 |
| 长名称、菜单在小屏上裁切 | 卡片存在 clamp / truncate；Select 默认绝对定位于滚动容器中 | A07、A13、B06 |
| scope 切换后旧数据或草稿继续出现 | 请求缺少取消 / 序列保护；同 Backend 下组件 key 不随 projectId 变化 | A16、B11 |
| 单击运行无可见反馈，双击重复提交 | 未见提交中禁用状态；卡片未绑定真实运行状态 | A10、B05 |
| 历史移动端重叠、双标题可能回归 | 已有移动 UI 问题记录；当前代码已有相应适配，但尚未实际应用确认 | A01、A13、A18 |

若上述风险实测复现，保留 FAIL。不能把现有行为直接批准为新基线。

## 10. 执行顺序与退出条件

1. 预检与数据准备：先确认两端版本、连接和数据集，建立初始截图。
2. D1 + M1 跑核心链与全部 P0；先抓卡片误触、scope 错误和静默失败。
3. D2 / M2 跑断点、横屏、字体、键盘和主题；执行 P1 及边界分支。
4. 修复后复跑失败用例及相关共享组件用例，再跑跨端核心链；经人工审阅后更新视觉基线。
5. 删除本轮普通测试数据，停用定时测试任务，恢复测试链路；系统内置项不在清理列表。

发布退出条件：

- D1 桌面应用与 M1 模拟器 APK 的全部 P0 子场景 PASS，无 BLOCKED / NOT RUN；N/A 必须有明确平台或能力依据，缺设备不算 N/A。
- 无错 Backend / Project 写入、误触运行 / 删除、不可达核心按钮、系统项误改等阻断缺陷。
- UI 与真实数据一致；请求失败不得冒充成功或正常空态；操作可理解且可恢复。
- P1 缺陷记录严重性、影响范围和处理决定；纯装饰偏差可单列评审，不掩盖交互问题。
- 报告列出两端成对截图、覆盖矩阵、未覆盖环境和剩余风险；不写未经验证的“全平台通过”。
