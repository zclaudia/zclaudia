# Open Design 能力迁移分阶段实施计划

日期：2026-10-23。状态：计划草案；P0 原型已完成，P1–P7 尚未实施。

目标是在 ZClaudia 中提供可长期使用的设计工作台，逐步覆盖 Open Design 的页面设计、可视编辑、模板、设计系统、演示文稿、媒体制作及作品审阅能力。继续复用 ZClaudia 的项目、工作目录、聊天、Agent 和 backend，采用内置设计核心与可替换的专业能力接口。

本计划先确定交付顺序与验收边界，不承诺日历工期。各阶段可独立发布；P5–P7 在进入实施前再细化具体工具、服务与成本。

## 当前基线

- [x] P0.1 内置「设计」面板，绑定当前会话及 backend。
- [x] P0.2 发现 HTML 文件，隔离预览静态 HTML/CSS 和本地资源。
- [x] P0.3 纯文本元素、文字颜色和背景颜色编辑，显式保存与修订冲突检查。
- [x] P0.4 生成与选区修改指令追加到现有聊天，沿用当前 Agent。
- [x] P0.5 自动化浏览器闭环，以及 macOS Tauri 中真实 Codex 生成、可视编辑、保存和重新载入验证。

P1（编辑与恢复基础）已于 2026-10-23 实现并通过自动化验收（设计见 [P1 实现设计](2026-10-23-design-workbench-p1-implementation.md)）：精确源码编辑引擎、撤销/重做、统一写入边界、持久快照与版本恢复全部落地，desktop/server 设计模块测试全绿。P2（完整静态工作台）亦于同日实现并验收（设计见 [P2 实现设计](2026-10-23-design-workbench-p2-implementation.md)）：多页面组织、画布视口、资源变化传播、源码联动与 ZIP 导出落地。真实 Agent + macOS Tauri 冒烟与远端 backend 验证仍待用户配合补做。

当前实现及验证记录见 [设计工作台原型](../design-workbench.md)。真实 Claude 尝试因重复工具查找取消，不计为通过；远端 backend、其他操作系统及动态页面尚未完成实测。

当前需要先解决的限制：

1. 元素主要依靠 DOM 层级序号定位；源码结构改变后可能失效。
2. 编辑会重新序列化整份 HTML，不能保证无关源码保持原样。
3. 没有撤销、持久版本历史和 HTML/CSS/图片整体恢复。
4. 面板检查 HTML 变化，独立 CSS 或图片更新未必触发预览重建。
5. 当前只允许受限静态编辑，不执行作品脚本。

## 架构约束

1. **项目文件是作品来源。** 历史快照用于恢复与分享；不另建一套与磁盘文件竞争的作品数据库。
2. **工作区身份与聊天身份分离。** 文件由 backend 身份、服务端解析的实际工作区和相对路径确定；session 用于授权与关联。相同工作区的多个聊天可以看到同一作品，不同 worktree 必须隔离。
3. **所有文件访问由宿主处理。** 预览 iframe 不持有宿主凭据，不接收可任意访问文件的 API。客户端不能自行指定可信根目录。
4. **按能力拆模块。** 设计文档、源码修改、预览、历史、素材、Agent 上下文和导出各自有接口，避免继续把逻辑堆进 `DesignPanel.tsx`。
5. **复用现有宿主能力。** 使用现有 workspace 布局、composer、Agent 生命周期、backend 路由和进程管理；不引入 Open Design 的 daemon、Electron 壳或第二套聊天运行时。
6. **编辑能力显式声明。** 能预览不代表能反向编辑。动态 DOM、第三方框架产物、复杂 CSS 和无法准确定位的元素应说明限制，不猜测修改目标。
7. **迁移代码与内容有来源记录。** 逐项记录源路径、上游提交和依赖；复制代码、模板及素材时保留对应许可证与通知文件，不能仅根据仓库总体许可推断素材许可。

## P1 编辑与恢复基础

目标：让已有文字和颜色编辑成为可靠的日常功能。分为 P1a 精确编辑、P1b 持久历史两个交付批次。

- [x] **P1.1 固定文档契约。** 定义工作区身份、文档修订、资源清单、选区定位、编辑事务及错误码。修订同时区分磁盘基线与预览草稿，迟到的 iframe 消息不能修改新版本。
- [x] **P1.2 精确源码修改。** 评估带源码位置的 HTML 解析器，仅替换目标文本或属性范围，保持无关字节、换行和注释。对隐式节点、重复属性、异常 HTML 或无法唯一定位的目标拒绝修改。解析器选择通过小型原型验证后确定。
- [x] **P1.3 选区定位。** 用源码范围、节点特征和文档修订验证目标；DOM 路径仅用于查找。重复文字、重复 id、兄弟节点插入等情况不得误改其他节点。预览专用标记不写入作品。
- [x] **P1.4 撤销与重做。** 为每个打开文档保留有界编辑序列，连续输入可合并，新编辑清除 redo。保存后仍可撤销为新草稿；外部版本接管、历史恢复或重新载入后重建基线。撤销不会绕过保存时的版本校验。
- [x] **P1.5 统一宿主写入边界。** 评估将现有文件锁与原子写入工具提取到通用文件层，供设计保存及宿主文件工具共用。保留修订校验、写前备份和文件元数据处理，避免从设计业务直接耦合 Pi runtime 内部模块。
- [x] **P1.6 持久快照。** 在应用数据目录存储内容寻址的二进制文件与快照清单，关联工作区、入口、来源和可确认的 run。首版覆盖入口 HTML 与清单内 CSS、图片、字体等本地资源；明确资源数量、单文件及总大小上限。未捕获的资源必须显示，不能标成完整快照。
- [x] **P1.7 版本列表与恢复。** 提供保存点、差异查看和恢复。恢复前检查当前文件修订并保存当前状态；恢复作为一个新版本。多文件恢复使用暂存、操作日志与失败恢复，不声称跨文件原子事务，不删除清单外文件。
- [x] **P1.8 明确样式覆盖行为。** 首版只写选中元素的 inline 声明，支持清除该声明。遇到外部 `!important` 等导致修改未生效时提示原因；不静默提高优先级或改写整个样式表。

外部 Claude/Codex CLI、shell 和其他编辑器不受进程内文件锁约束。对这些写入采用变化检测、保存前校验、快照和冲突处理；检测到同工作区 Agent 正在运行时给出明确状态。不能把“共用锁”描述为消除所有外部并发覆盖的保证。

快照也不能假定外部写入已经停止：捕获前后验证各文件的哈希与元数据，仅接纳校验一致的文件；检测变化后重试或标记失败，持续变化不能静默当成成功。这只能发现观测到的变化，不保证任意外部写入下多个文件处于同一时刻。界面区分「资源清单已完整捕获」与「同一时刻一致」，首版不承诺后者。

**验收：**

- 相同工作区的两个聊天看到一致历史；不同 backend/worktree 不串文件或草稿。
- 修改一个标题时，无关源码字节不变；旧选区、重复节点与无效源码不会被猜测匹配。
- 撤销、重做、保存、重新载入和冲突处理符合上述基线规则。
- HTML、CSS 与二进制图片可组成快照并恢复；恢复中断后能明确报告并恢复到可用状态。
- 对受控写入验证互斥与过期修订拒绝；对外部写入验证已观测冲突保留草稿、备份可恢复。
- 路径越界、符号链接、私密文件、超限资源和错误 snapshotId 无法绕过工作区校验。

## P2 完整静态工作台

目标：把窄面板扩展为可以管理多页作品的设计工作区，复用现有面板最大化和布局能力。

- [x] **P2.1 页面组织。** 文件标签、缩略图、最近打开状态与每页草稿。文件删除、改名、关闭未保存页面都有明确处理；状态按工作区隔离。
- [x] **P2.2 画布视口。** 缩放、适应可用区域、桌面/平板/手机宽度与自定义尺寸。缩放只影响显示，不改变保存的 CSS，也不改变用于响应式布局的逻辑视口。
- [x] **P2.3 资源变化传播。** 追踪打开作品的 HTML/CSS/图片依赖；宿主写入事件优先，按需 watcher 或哈希轮询兜底。干净页面刷新，脏页面保留草稿并提示外部更新；关闭面板释放监听。
- [x] **P2.4 源码与预览联动。** 提供查看选区源码、跳转文件和差异预览，沿用现有文件查看/编辑入口。明确哪个编辑器持有未保存草稿，避免两份草稿互相覆盖。
- [x] **P2.5 基础导出。** 导出当前明确版本的 HTML 与本地资源 ZIP，校验资源完整性。未保存草稿先明确选择保存或导出草稿，导出失败不能生成看似完整的包。

**验收：** 同一会话管理三页静态作品，分别编辑与保存；仅 CSS 或图片变化也会刷新；切换会话/backend 后旧请求不会污染当前页；设备宽度与缩放独立；导出包在离线条件下可打开且资源齐全。

## P3 扩展可视编辑

目标：逐步减少简单修改对 Agent 的依赖，所有编辑继续经过 P1 的事务与源码修改接口。

- [ ] **P3.1 排版与盒模型。** 字体、字号、字重、行高、对齐、宽高、内外边距、边框与圆角；输入有单位与范围校验，支持清除工具写入的覆盖值。
- [ ] **P3.2 图片与链接。** 本地图片替换、alt、裁切显示、链接文字和目标；通过宿主资源引用接口选择素材，保持相对路径可移植。
- [ ] **P3.3 元素导航。** 选择父级/子级、结构树、选区高亮、只读原因。SVG、伪元素、脚本生成节点与无法映射的内容有明确能力边界。
- [ ] **P3.4 受限结构修改。** 从独立节点的复制、删除、同父级排序开始，再做容器内移动。处理 id 重复、锚点引用及布局变化；修改后重新建立定位，支持一次操作整体撤销。
- [ ] **P3.5 CSS 来源编辑。** 先显示生效规则和覆盖原因，再支持受控的本地 CSS 声明修改。外部样式表写回依赖 CSS 源码位置、P1 多文件恢复和 P2 资源刷新；无唯一来源时保留显式 inline override 方案。

**验收：** 选一张卡片修改排版、间距、图片和链接，再复制、排序、撤销、保存与重载；结果与源码一致。普通样式、`!important`、媒体查询及简写属性都覆盖测试；不能可靠处理的组合明确拒绝，不破坏原布局源码。

P3.5 是独立交付批次，不阻塞先发布 P3.1–P3.4。自由拖拽绝对定位画布及任意 React/Vue 组件源码反向编辑不包含在本阶段。

## P4 模板与品牌体系

目标：从“每次重新描述页面”发展为可复用的设计起点和持续一致的 Agent 上下文。

- [ ] **P4.1 模板清单。** 先选落地页、仪表盘、移动原型和静态展示页等少量模板，记录入口、所需能力、资源、来源与版本。模板复制到工作区后可以独立编辑；更新模板不覆盖用户作品。
- [ ] **P4.2 品牌与设计系统。** 颜色、字体、间距、圆角、logo 和使用规则落为可读项目文件，例如 `DESIGN.md` 与 CSS tokens；明确全局资产和项目副本的关系。
- [ ] **P4.3 素材库。** 导入本地图片、SVG 与字体，支持预览、重名处理和被引用提示；模板素材、用户素材与后续生成素材共用资源引用契约。
- [ ] **P4.4 Agent 设计上下文。** 组合当前文件与修订、选区定位、相关源码、可用的选区截图、品牌规则和素材引用，并在发送前可见。继续走现有 composer 和运行通道，禁止跨 backend 取错内容。
- [ ] **P4.5 生成与续改反馈。** Agent 写入后更新文档及恢复点，记录可确认的来源；没有写出文件、运行失败或已取消时明确显示状态，不以消息结束代替作品成功。

**验收：** 选择品牌与模板，经真实 Agent 生成页面；局部续改保持品牌和已有手动修改；素材替换后重开可用；当前上下文及待发送内容可检查。自动测试覆盖上下文结构，真实 Agent 冒烟验证实际产物，不能只靠 prompt 文本断言设计质量。

## P5 交互原型与演示文稿

目标：支持超出静态页面的作品类型。拆为 P5a 交互预览、P5b 演示文稿与导出。

- [ ] **P5.1 预览执行边界。** 区分静态编辑、交互运行和演示模式；为作品脚本提供隔离来源及受控资源服务，不能简单放开宿主同源权限。定义导航、网络、存储、弹窗和消息桥接策略。
- [ ] **P5.2 交互原型。** 支持本地多页跳转、菜单、弹窗等声明范围内的交互；编辑与运行模式可以切换。动态节点若无法映射回源码，只能交给 Agent 或只读查看。
- [ ] **P5.3 演示文稿。** 固定一种 HTML deck 约定，支持缩略图、页面排序、演讲者备注、键盘翻页、全屏演示与比例设置，再扩展其他模板协议。
- [ ] **P5.4 渲染与导出。** 从 PNG 和 PDF 开始，复用同一明确版本和资源包；分别验证字体、分页、截图与实际预览。PPTX 另做可行性验证，区分可编辑元素与整页图片，界面不能混称。

**验收：** 交互作品可运行但不能访问宿主凭据或文件接口；切换编辑模式后仍能定位支持的节点。三页 deck 可排序、编辑、播放、保存和重新打开，PDF 页数与页面内容一致。macOS Tauri 与浏览器分别验证。

任意项目开发服务器代理与 React/Vue 源码反向编辑仍是独立扩展，不作为 P5 完成条件。

## P6 图片与视频能力

目标：以独立任务接入专业媒体能力。先图片、后视频，每项能力独立开关和验收。

- [ ] **P6.1 媒体任务接口。** 定义输入素材、生成参数、产物、进度、取消、失败与重试；复用已有任务和进程生命周期。提交去重，结果按工作区归属写入素材库。
- [ ] **P6.2 图片生成与编辑。** 先接一个选定的 provider，支持生成、基于现有图片修改及替换到页面。沿用宿主凭据管理，不在设计文件中保存密钥。
- [ ] **P6.3 模型与费用体验。** 用户能看到所选服务、任务状态以及服务支持的费用/用量信息。不能精确报价时明确表示估算或未知；重试不能无提示重复提交收费任务。
- [ ] **P6.4 动效与视频验证。** 选择一种可复现的 HTML 动效渲染路线，验证运行依赖、音频、尺寸、帧率、取消及导出，再决定是否迁移 HyperFrames 适配。通过进程管理运行渲染器。
- [ ] **P6.5 媒体交付。** 大文件分块或流式传输，避免现有 JSON/base64 接口承担全部媒体；生成失败不替换原素材，成功产物进入历史及导出资源清单。

**验收：** 真实服务生成图片并替换到页面，取消或重试有明确结果且不丢旧素材；短动效可预览并导出可播放 MP4，任务取消后相关进程退出。每个 provider 独立验收，不以 mock 成功代表真实服务可用。

## P7 分享与审阅协作

目标：先分享和审阅明确版本，再评估多人同时编辑。分享服务与身份方案在本阶段开始时确定，不能假定现有 gateway 已具备外部作品托管能力。

- [ ] **P7.1 不可变分享快照。** 分享指定版本及其资源包，支持访问范围、撤销和必要的过期策略；排除本机路径、凭据与无关项目文件。
- [ ] **P7.2 页面与元素评论。** 评论绑定快照和元素定位；新版本中找不到对应元素时显示失效，不将反馈静默挂到其他元素。
- [ ] **P7.3 审阅到 Agent 修改。** 用户选择评论后，组合原版本、当前版本与反馈进入现有聊天，Agent 写入后形成新恢复点；旧分享仍显示原版本。
- [ ] **P7.4 多人同时编辑评估。** 有实际需求后再选择文档锁、操作同步或 CRDT/OT；明确离线、冲突、删除及恢复语义，不把评论同步当成实时共同编辑。

**验收：** 第二个独立客户端只能访问授权快照；旧分享不会随本地修改变化；访问撤销生效；评论能回到正确版本与选区；按反馈生成新版本后，旧版仍可审阅和恢复。

## 交付里程碑与验收方式

| 里程碑 | 包含阶段 | 一次完整演示 |
|---|---|---|
| M1 稳定静态工作台 | P1 + P2 | 真实 Agent 生成三页作品，设备视口检查，可视编辑、撤销、保存、外部冲突、版本恢复、离线 ZIP |
| M2 日常设计能力 | P3 + P4 | 从品牌模板起步，替换素材、调整样式与结构，交给同一 Agent 续改，比较和恢复版本 |
| M3 扩展作品与审阅 | 分批交付 P5、P6、P7 | 交互/Slides、图片/视频、版本分享分别完成自身闭环；无需捆绑一次发布 |

每批交付保留以下证据：

- 源码修改、路径、版本、失败恢复等关键行为的针对性单元/接口测试。
- 使用确定性 Agent 测试桩的应用集成测试，保证协议与状态可重复验证。
- 至少一次真实 Agent + macOS Tauri 冒烟；按功能新增浏览器及远端 backend 验证。
- 涉及文件时，核对磁盘内容和重新打开后的结果；涉及视觉输出时，检查实际截图或导出文件。
- 构建与仓库要求的检查；既有失败和本批引入的失败分别记录。

支持范围按实际验证的平台和 runtime 记录。Claude 当前工具选择循环单独跟踪，不阻塞已通过的 Codex 设计链路，也不因此宣称 Claude 已验证。

## Sub-agent 与 Luna 分工

每轮由主代理负责契约、集成与最终验收，最多并行三个 Luna 子代理。共享契约先由一个负责人修改，其他代理基于契约开发，避免同时改同一入口文件。

| 工作流 | 独立任务 | 主要文件边界 |
|---|---|---|
| 编辑核心 | 定位、精确源码 patch、事务和 fixture | `features/design` 的纯逻辑模块与对应测试 |
| 后端文档 | workspace 解析、保存、快照、资源变化 | `server/src/application/design`、独立 infra 与 HTTP 路由 |
| 面板与体验 | 标签、视口、历史 UI、现有聊天衔接 | `DesignPanel` 拆出的组件与 workspace 适配 |
| 主代理 | 公共 types/API、跨模块变更、集成和真实 Tauri 验收 | 集成入口及共同契约 |

模板筛选、来源清单、导出适配和媒体 provider 可在相应契约稳定后成为独立任务。先提交或汇合一个可运行的纵向功能，再扩下一项，不能等所有子模块完成后才第一次集成。

## 第一轮可执行任务

第一轮仅实施 P1a，不把多页面、模板或媒体一起展开。

1. **T1 契约与 fixture。** 固定工作区/文档/选区/事务结构，建立包含重复节点、嵌套文本、异常 HTML、CSS 覆盖及外部修改的测试样本。
2. **T2 精确修改引擎。** 验证解析器并替换整文序列化，先保持原有文字、文字颜色和背景色三种能力。
3. **T3 编辑历史。** 加 Undo/Redo、清除颜色覆盖和草稿状态，明确保存与重新载入的行为。
4. **T4 写入边界。** 对齐宿主锁与原子写入接口，保留工作区校验及修订冲突处理，避免扩大可写路径。
5. **T5 集成验收。** 在现有咖啡页面及测试样本上完成“选择 → 修改 → 撤销/重做 → 保存 → 外部修改冲突 → 重开”，检查无关源码字节保持原样。

T1 完成后，T2、T4 与历史 UI 可并行；T3 的状态整合依赖 T2 的事务输出。T5 通过后进入 P1b 的持久快照与恢复，再交付 M1。
