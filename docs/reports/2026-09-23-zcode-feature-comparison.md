# ZCode 功能对比与借鉴清单（2026-09-23）

对象：`~/Code/ZCode`，智谱开源的 AI 编程工作台（Electron 桌面 + Web + TUI + 自研 Agent CLI，Apache-2.0，根 package 版本 3.14.0，CLI 0.16.9）。
方法：五个方向并行读源码（产品 UI、Agent 运行时、后端与远程、工程实践、zclaudia 现状），只列 ZCode 有而 zclaudia 缺或明显弱的部分。
表中 ZCode 路径相对 `~/Code/ZCode`，zclaudia 路径相对本仓库根。

## 0. 前提

- ZCode 仓库是脱敏导出，只有两个 commit。specs、docs、CI、husky、lint-staged、E2E 套件全部被剥掉，只剩配置里的残留引用。本文评估的是设计，不是它的测试覆盖。
- `packages/superpowers-plugin` 只有 LICENSE；`packages/zcode-cua` 是 fail-closed 空壳；权限 `auto` 模式声明了但未实现。
- 两个项目重叠面很大：git 面板、终端、diff、浏览器面板、自动化、worktree、插件、MCP、权限系统、用量统计双方都有，不再列入。

推荐度：★★★ 缺口明显且收益直接；★★ 有价值但要做设计取舍；★ 可做可不做。

## 9. 建议落地顺序

1. 架构门禁与 i18n 骨架。都是越晚越贵的基建，架构门禁可以先只 manage 一个 server 域跑通 baseline。
2. 文件 checkpoint / rewind + steer + pending-command 恢复。三者都落在会话主链路，一起设计可以共用 turn 级的 seq 与快照。
3. 从 Claude Code / Codex 导入会话与配置。运行时已接入，缺的是扫描和映射。
4. 插件商店。先按 CONTEXT.md 的方式把术语定下来，再做 Public / Personal 两段。
5. 远程可回放流语义与 owner / lease。放在移动端重连稳定性问题暴露之后再做，避免过早引入复杂度。

调研原始结论存于 Claude 记忆 `zcode-reference-survey`。
