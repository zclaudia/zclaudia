# 内置 Agent 工具集对比：Pi runtime vs ZCode CLI（2026-09-23）

对象：zclaudia 内置 Pi runtime 的工具集（`server/src/infra/providers/pi-runtime/`，名字全集在 `shared/src/core/tools.ts`）与 ZCode CLI 的内置工具集（`~/Code/ZCode/apps/zcode-cli/packages/core/src/tool/handlers/`）。
目的：找出对齐 ZCode 时需要补的差距，同时标出 zclaudia 已经领先、对齐时不能丢的部分。
ZCode 路径相对 `~/Code/ZCode/apps/zcode-cli`，zclaudia 路径相对 `server/src/infra/providers/pi-runtime/`，另有说明除外。

## 0. 总体结论

| 维度         | 谁领先   | 一句话                                                                                                                                                                                                                                                                 |
| ------------ | -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件读写编辑 | zclaudia | Read 有 ranges / hashline / 结构大纲 / notebook；Edit 有批量、多文件 patch、hashline 锚点、预览、死循环守卫；另有 MultiEdit、ReadSymbol / EditSymbol、AstGrep / AstEdit。ZCode 只有朴素的 Read / Write / Edit，ApplyPatch 和 MultiEdit 都没实现                        |
| Shell 安全   | 各有侧重 | zclaudia 有沙箱与升级协商、关键命令闸门、敏感路径与文件绕过守卫；ZCode 有可证明的只读命令分类器，能让只读命令免审批                                                                                                                                                    |
| 网络         | 各有侧重 | zclaudia WebFetch 有 SSRF + DNS pinning、多格式；WebSearch 有 Brave → SearXNG → DDG 链。ZCode WebFetch 用辅助模型按 prompt 摘要、带缓存和文档域名预批                                                                                                                  |
| MCP / Skills | zclaudia | 通用 MCPTool、ToolSearch、资源读取、9 个外部元工具、6 个 skill 元工具；ZCode 只注册具体 `mcp__*` 工具和一个 Skill 工具                                                                                                                                                 |
| 子代理与编排 | ZCode    | 命名 agent 类型、SendMessage 给运行中的子代理、RespondToCoordinator、ReadSessionContext、Cron 系列工具。zclaudia 只有单一类型的 Agent + TaskOutput + Monitor                                                                                                           |
| 执行框架     | ZCode    | 每个工具声明 readOnly / destructive / concurrentSafe / timeout / 输出预算 / 副作用范围 / 风险；拓扑排序 + 并发分组调度器；resolveInput → hook → 审批 → 可暂停超时 → 序列化 → PostToolUse 的固定管线。zclaudia 靠 pi-agent-core 的 Promise.all 并发，安全性靠工具内部锁 |

对齐的重点应放在**执行框架**和**编排类工具**，文件编辑类不需要动。

## 2. 执行框架对比

| 项             | zclaudia                                                                                                                                                                             | ZCode                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | 差距                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 工具契约元数据 | `BUILTIN_TOOL_METADATA`：declaredReadOnly、mutatesWorkspace、riskLevel。工具对象上无 readOnlyHint / executionMode                                                                    | 每个 ToolEntry 声明 readOnly、destructive、concurrentSafe、timeoutMs / maxMs / allowCallOverride、maxOutputBytes、sideEffectScope（none / session / workspace / network / system / userInteraction）、riskLevel、needsApproval、alwaysAsk、askOptions、resultBudget（strategy truncate / artifact，inline / model 上限，head / tail，retention）。`contracts/src/tools/contract.ts`                                                                                                                                               | **大**。这是调度、审批、预算三件事的共同基础                                                                                                            |
| 并发调度       | pi-agent-core 0.84.1：批次内全部 Promise.all，除非 `config.toolExecution = sequential` 或某工具 `executionMode = sequential`。zclaudia 两者都没设。安全靠工具内部的路径写锁和 ledger | `ToolScheduler`：按 `dependsOn` 拓扑排序分层，层内把可并行调用打包成 ≤10 的组，不可并行的单独成组。判定顺序：destructive → 否；concurrentSafe 显式 → 按值；readOnly → 是；否则 sideEffectScope 为 none。`turnControl.stopTurnAfterResult` 后取消后续组。`tool/scheduler.ts`                                                                                                                                                                                                                                                       | **大**。当前 Bash 与 Edit 同批会并发跑。最小改法是给写类工具设 `executionMode: sequential`，但会让整批退化为串行；完整改法要接管 pi 的 executeToolCalls |
| 执行管线       | `beforeToolCall` 权限闸门 → 执行 → `truncateContent` → 失败循环守卫、修复提示、洪泛提示、遥测 → 用户 hooks（PreToolUse 串行、PostToolUse 追加）。`agent-hooks.ts`                    | 固定 12 段：注册表别名解析 → 追踪 span → schema 校验 → `validateInput` → **`resolveInput`**（审批前把执行事实定下来，hook、规则、对话框、handler 看到同一份字节）→ PreToolUse hook（updatedInput 重校验）→ 权限（capability 解析、项目规则、PermissionRequest hook、**`prepareApproval`** 只能把 ask 收窄为 proceed 或附预览，抛错即 ask）→ ToolCallStarted → **可暂停超时**（模型请求排队时暂停计时）→ handler → validateOutput → serializeOutput → PostToolUse → **PostToolUseFailure** → 事件与遥测。`executor/call-runner.ts` | 中。zclaudia 缺 resolveInput / prepareApproval 分层、per-tool 超时、PostToolUseFailure                                                                  |
